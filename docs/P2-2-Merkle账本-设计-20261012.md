# P2-2 设计：账本 Merkle 化（防"合谋截断"）

> **目标**：把账本从「线性哈希链」升级为「Merkle Tree 承诺」，堵住当前**唯一未防的账本攻击**——**合谋截断尾部事件后重算**。
> **范围**：只改 `agentlink/ledger.py`（+ 少量 `node.py` 交换字段），**不动密码学层（P2-1）、不动传输层**。
> **风险**：中低。账本模块自包含，可单测 + 真机独立验证；不改 E2EE 握手。
> **状态**：设计稿（待老哥确认后实施）

---

## 一、为什么需要（当前漏洞）

现有账本是一条**线性哈希链**：
```
H0=H(genesis‖ev0) → H1=H(H0‖ev1) → H2=H(H1‖ev2) → ... → 链尾=Hn
sig_object = sha256(Hn_initiator ‖ Hn_responder)
```

**已有的防护**（v0.3.1）：
- ✅ 改中间任一事件 → 链断 → `verify()` 报 `hash chain broken`
- ✅ 改任一 hash → sig_object 变 → 暴露（C3 防分叉）

**🔴 未防的漏洞——合谋截断**：
```
攻击者（双方合谋，或一方控制对端）：
  ① 删掉链尾若干敏感事件（如"降级为明文""收了个可疑帧"）
  ② 重新计算链尾 hash Hn'（合法，链是自洽的）
  ③ 双方用 Hn'_initiator ‖ Hn'_responder 重算 sig_object'
  ④ 对方对该 sig_object' 重新签名
  → verify() 全过！篡改被"合法化"
```

**根因**：`sig_object` 只承诺**链尾一个值**（Hn），而链尾可以由"任意前缀 + 重算"得到。**承诺不绑定"承诺时的事件集合"**。

**Merkle 修法**：`sig_object` 承诺**整棵树的 root**——root 是对**全部事件**的密码学承诺，**删任何一个事件 root 必变**。

## 二、设计

### 2.1 数据结构

每个事件加一个 `leaf`（叶子哈希），账本加 `merkle_root`：

```python
# LedgerEvent 增字段
leaf: Optional[str] = None   # leaf = sha256(canonical(event_content))  —— 与现有 hash 输入同源

# SessionLedger 增字段
merkle_root: Optional[str] = None   # 全部参与事件（排除 hash_exempt）的 Merkle root
```

**leaf 与现有 hash 的关系**：
- 现有 `event.hash` = `H(prev_hash ‖ seq ‖ content)`（链式，含位置）
- 新增 `event.leaf` = `H(seq ‖ content)`（**独立**，不含 prev——Merkle 需要的"位置无关"叶子）
- 两者**并存**：链保留（向后兼容 + 逐事件定位篡改），Merkle 叠加（整集承诺）

> ✅ 关键：**不删链**。链能精确指出"第 N 个事件坏了"，Merkle 只能指出"集合变了"。两者互补。

### 2.2 Merkle 构造

```python
def _merkle_root(leaves: list[str]) -> str:
    """标准二叉 Merkle：相邻两两 sha256 拼接，奇数则最后一个自复制（防二次原像攻击）。
    leaves 为空 → 返回 sha256("")（空集承诺）。
    """
    if not leaves:
        return "sha256:" + _sha256_hex(b"")
    level = [bytes.fromhex(l.split(":")[1]) for l in leaves]
    while len(level) > 1:
        if len(level) % 2 == 1:
            level.append(level[-1])          # 奇数复制末项（RFC 6962 风格）
        level = [hashlib.sha256(level[i] + level[i+1]).digest()
                 for i in range(0, len(level), 2)]
    return "sha256:" + level[0].hex()
```

**约定**（写死进协议，避免歧义）：
- 叶子顺序 = 事件 seq 升序（不含 hash_exempt 事件）
- 奇数节点自复制（**不是** 升级后直接进下一层——那会造出"CVE-2012-2459"二次原像漏洞）
- 空集 root = `sha256("")`

### 2.3 sig_object 升级（v0.4）

**现状**：
```python
sig_object = sha256(Hn_initiator ‖ Hn_responder)     # 只有链尾
```

**升级**：
```python
sig_object = sha256(
    "agentlink-sig-v2" ‖
    merkle_root_initiator ‖ merkle_root_responder ‖   # 整集承诺（核心）
    pub_fpr_initiator ‖ pub_fpr_responder         ‖   # 绑定身份（防换人）
    started_at                                        # 绑定会话时点（防跨会话重放）
)
```

**为什么加 pub_fpr 和 started_at**：
- `pub_fpr`：防止攻击者用**另一对密钥**生成一个 merkle_root 一致的账本（虽然极难，但显式绑定更干净）
- `started_at`：防止把**A 会话的账本**整套搬到 **B 会话**（重放）

> ⚠️ **兼容性**：这是 **sig_object 格式变更** → 两端必须同步升 v0.4，与 v0.3 互不验签（跨版本握手会失败）。走"双层签名"过渡见 §4。

### 2.4 verify() 升级

```python
def verify(...):
    # 1) 重算链（保留：逐事件定位）
    # 2) 重算 merkle_root：leaf 列表 → root，对比 self.merkle_root
    #    ❌ 不符 → "merkle_root mismatch: 事件集合被改（疑似截断/插入）"
    # 3) 重算 sig_object（用新公式）并比对
    # 4) 真实验签（不变）
```

**新增校验点**：`out["merkle_ok"]`。

### 2.5 落盘格式

`.jsonl` 每行事件加 `leaf`；`_meta` 行加 `merkle_root`；`.sig` 加 `merkle_root` + `sig_object_version`。

**向后兼容**：`load()` 时若检测到老账本（无 `merkle_root`），标 `legacy=True`，`verify()` 走旧的"仅链"路径（不报错，但结果里 `merkle_ok=None` 并提示"老账本，未做 Merkle 校验"）。

## 四、迁移策略（关键：不炸真机）

P2-2 改了 sig_object 格式 → **跨版本互不兼容**。三种过渡：

| 方案 | 做法 | 取舍 |
|:--|:--|:--|
| **A 硬切** | 直接升 v0.4，两端同步 | 简单，但过渡期跨版本会话失败 |
| **B 双签过渡** | sig 里同时带 v1 和 v2 两个 sig_object + 两套签名，对端能验哪个用哪个 | 平滑，但复杂度高、多一轮签名 |
| **C 版本协商（推荐）** | 握手第①轮互换 `sig_version`；双方都支持 v2 则用 v2，否则回落 v1 | 平滑 + 复杂度适中 |

**推荐 C**：握手第一轮多带一个 `sig_version: 2` 字段；两端都报 2 → 走 Merkle + v2 公式；任一端是旧版 → 回落 v1（**并在账本里记一条 `merkle_disabled: true` 的降级事件**，审计可见）。

## 五、测试方案

### 单测（新 `tests/test_merkle.py`）
1. **截断攻击**：造 5 事件账本 → root → 删尾部 2 条 → 重算链（链仍自洽）→ **verify 必须报 merkle mismatch**（这是本设计存在的理由，头号测试）
2. **插入攻击**：中间插一条 → root 变 → 检出
3. **root 复现性**：同事件序列两次构造 → root 相同
4. **空集 / 奇数叶**：边界
5. **leaf 独立性**：改 seq 或 content → leaf 变
6. **老账本兼容**：v0.3 账本 load → `legacy=True`，verify 走链路径不报错
7. **v2 sig_object 绑定**：改 pub_fpr / started_at → sig_object 变

## 七、明确不做（本次边界）

- ❌ **外部锚定**（把 merkle_root 发到时间戳服务/另一条链）——这是 P2-2 的"可选加强"，但引入外部依赖，**本次不做**，留作 v0.5。
  （理由：没有外部锚定，**双方合谋仍可整体重造一棵新树**；Merkle 挡的是"单方改/删"，挡不住"双方彻底重演"。要挡后者必须外部锚定——但那是更大的工程 + 依赖，先不做，README 如实标注"挡单方，不挡双方合谋重演"。）
- ❌ 换哈希算法（仍用 SHA-256）
- ❌ 动 P2-1（密码学层）

## 八、诚实说明（要写进 README）

Merkle 化把账本防护从"防单方改单事件"提升到"**防单方改/删/插任意事件**"，但：
- **仍不防"双方合谋整体重演"**——两方可以一起造一棵全新的、自洽的树，各自签名。要防这个必须**外部锚定**（v0.5）。
- **仍依赖"签名密钥不泄露"**——密钥泄露则可伪造任意账本。
- 结论：**Merkle 把攻击成本从"改一个 hash"抬到"重造整棵树 + 双方配合"**，是显著加强，但**不是"不可篡改"**。
