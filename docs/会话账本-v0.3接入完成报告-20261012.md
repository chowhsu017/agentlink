## 三、签名对象定义（本版核心）

```
sig_object = sha256( H_initiator_view ‖ H_responder_view )
             ↑ 按会话角色定序（initiator 在前），非本地视角

发起方算：sha256(H_A ‖ H_B)
响应方算：sha256(H_B ‖ H_A)  ← is_initiator=False → 内部交换顺序
→ 两端得到同一对象 → 双签才成立
```

**两轮交换时序**：
```
hangup
 ├─ 轮①：互发链尾 hash
 ├─ 各自算 sig_object（需双方 hash）
 ├─ 各签 sig_object
 └─ 轮②：互发签名
→ record_signature_exchange（含 sig_object/self_hash/peer_hash）
→ seal → attach_signatures（按角色安放）→ save
```

## 九、D3 修复：IPv6/IPv4 双栈兼容（2026-10-12 07:22）

### 问题（真机实测确认）

```
双端 uvicorn 绑 0.0.0.0 → 只监听 IPv4（lsof: TCP4 *:18790）
macOS getaddrinfo 对 .local 主机名 IPv6-first（有 AAAA）
websockets 不做 Happy Eyeballs → 首试 IPv6 → 对端无监听 → 5s 超时
（httpx 有 Happy Eyeballs 回退 → 侥幸能连，所以此前只有 WS 挂）
```

实测：`websockets.connect("ws://peer-b…local:18790/…")` → `TimeoutError` 5.0s。

### 修法

新增 `agentlink/netutil.py`：`prefer_ipv4_url(url)` 把 host 解析为 IPv4（集中化，防各脚本 ad-hoc 补丁）。
应用点：
- `agentlink_call_peer.py` / `agentlink_responder_call.py`（替换 `_force_ipv4`）
- `agentlink/node.py` `call()`（peer WS + HTTP 一并归一）
- 逃生开关：`AL_PREFER_IPV6=1`；调试：`AL_NET_DEBUG=1`

> **为什么不做服务端双栈（方案 A）**：uvicorn `host="::"` 在本机是 **IPv6-only**
> （实测 V6ONLY 未关，IPv4 连不上）；且本环境 IPv6 互通不可靠（ping6 100% 丢包）。
> 服务端全 IPv4，客户端显式选 IPv4 是最小、最稳、直击根因的修法。

### 实测结果

| 项 | 修复前 | 修复后 |
|:--|:--|:--|
| 主机名 WS 连接 | 5.0s 超时 | **0.028s** |
| 发起方 → 响应方（主机名）| 靠 `_force_ipv4` 硬转 | ✅ 自动 IPv4 |
| 响应方 → 发起方（主机名）| ❌ 超时 | ✅ 33 条结果回传 |

**踩坑（已修）**：对端联动脚本在对方家目录，`sys.path.insert(0, SRC)` 只加了家目录，
而包在 `agentlink-demo/` → 导入到 site-packages（v0.1.0，**无 netutil.py**）→ `except: pass` 静默吞掉。
已改为也插入 `agentlink-demo`（P-004 静默失效教训再现）。

**新增测试**：`tests/test_netutil.py`（7 项）。**53 passed**（原 46）。

## 十、闭合：initiator 路径建账本（2026-10-12 07:27）

### 问题（v0.2 遗留缺口）

`SecureSessionManager.on_accept()` 的 **initiator（呼叫方）路径只建 cipher、不建账本**：
- `on_ring()`（响应方）→ 建账本（`is_initiator=False`）✅
- `on_accept()`（呼叫方，无 cipher 时）→ 只建 cipher → **呼叫方全程无审计记录** ❌

### 修法

在 `on_accept()` 的 initiator 分支末尾，cipher 建好后补：
```python
if peer_enc_b64 and peer_sign_b64 and self.ledger is None:
    self._start_ledger(sid, peer_did, peer_sign_b64, is_initiator=True)
```
- 角色正确：呼叫方 `_is_initiator_view=True`（sig_object 定序用）
- 顺手：`_start_ledger` 支持 `_ledger_dir_override`（测试隔离用，避免污染 `~/.agentlink`）

### 验证

- 新增 `test_v03_initiator_accept_creates_ledger`：断言 initiator 建账本、角色 True、能记帧、能封存。
- **54 passed**（原 53）；真机跨机调用无回归（双签齐备）。

> 注：node-less 的 p1 呼叫方目前只做到「建账本 + 记帧 + 单签封存」；
> 双向两轮交换需在 hangup 时主动发起（与 responder 对称）——属进一步工作，不阻塞本缺口。
